1 Project Objective

Minimize Bits Per Byte (BPB) on a held-out evaluation corpus (dev_eval.txt) within hard constraints: ≤ 2,000 optimizer steps, ≤ 2,000,000 parameters, provided training corpus only, pure PyTorch / NumPy / stdlib, CPU-compatible, evaluate.py unchanged.

Each experiment was designed to answer exactly one binary research question so that causal attribution remained unambiguous. The scope was constrained from the outset to prevent confounding factors.

3 Experimental Methodology

Each experiment modified exactly one variable and kept everything else byte-for-byte identical to the baseline. A dedicated training script (train_expNN.py) and runner script (run_experimentNN.ps1) were created per experiment so that the original files were never modified until a winner was confirmed. All artifacts (training logs, evaluation logs, checkpoints, config, metrics) were saved and committed to GitHub for reproducibility.

  • 4 hypotheses tested over 4 experiments + 1 baseline.
  • Each experiment ran exactly 2,000 optimizer steps with the same random seed (1337).
  • The primary metric was dev BPB from the unmodified evaluate.py.
  • Human decisions drove experiment selection; code implementation was AI-assisted.

5 Why Experiment 04 Won

Root Cause Analysis

The baseline model used only 1,339,840 parameters out of the 2,000,000 allowed — just 67% of the available budget. With 2,000 training steps and a small-but-complete corpus, the model was capacity-constrained: it lacked enough representational bandwidth to fit the training signal, not regularization or schedule problems.

Experiments 01–03 tested regularization and efficiency levers (AdamW, LR scheduling, weight tying). All three worsened BPB, confirming the model was underfitting, not overfitting. The real constraint was model size.

Experiment 04 increased n_embd from 160 to 192. This single change scales all projection matrices — token embeddings, Q/K/V, output projection, and both MLP linear layers — simultaneously, giving the model significantly more capacity at every layer. The result was a clean −0.0246 BPB improvement with no other changes.

8 Engineering Conclusions

  • Model capacity was the binding constraint. At 2,000 steps, regularization (AdamW, scheduling) was counterproductive because the model was underfitting, not overfitting.
  • LR scheduling is harmful at very short training budgets. Cosine decay reduces the effective step size near the end of training, wasting compute budget when the model needs to keep learning.
  • Weight tying slightly hurts when parameter budget is unused. Sharing embedding and head weights reduces flexibility while offering no compensation when more parameters are available.
  • Scaling n_embd is the highest-ROI change. It uniformly increases representational bandwidth at every layer for a cost of ~563k additional parameters — well within the 2M cap.
  • Ablation-first is the right scientific approach. By isolating variables, we avoided compounding failures and obtained clear causal evidence for each decision.
