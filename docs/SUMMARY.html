1 Project Overview

The objective of this project is to minimize Bits Per Byte (BPB) on a held-out evaluation text (dev_eval.txt) under strict operational constraints:

  • Maximum 2,000,000 parameters (Checked at grading)
  • Maximum 2,000 optimizer steps in training
  • Pure PyTorch / NumPy / stdlib (No pretrained weights or external framework dependencies)
  • CPU-compatible execution
  • Unmodified evaluate.py contract with 100% byte-fallback roundtrip verification

4 Why Experiment 05 Won

Key Engineering Insight

The baseline model was doubly constrained by raw byte tokenization and obsolete positional/MLP architecture. Subword BPE tokenization compressed the 5.7MB text corpus from 7.3M raw bytes into 6.0M tokens. By grouping UTF-8 multi-byte sequences (especially Devanagari/Hindi characters) into single subword tokens, the model's effective context window was extended without increasing sequence length.

Combined with zero-parameter Rotary Position Embeddings (RoPE), SwiGLU gated activations, RMSNorm, and Weight Tying, the model achieved unprecedented parameter efficiency. Tying token embeddings to the lm_head saved 98,304 parameters, which were re-allocated to increase hidden representational width ($n_{embd}=192$, $n_{head}=6$, $hidden_{dim}=512$).

7 Engineering Lessons Learned

  • Constraint Diagnosis First: Optimizers and schedulers (AdamW, cosine decay) failed because the model was underfitting, not overfitting. Regularization worsens underfitting.
  • Subword Compression is King for BPB: Compressing UTF-8 multi-byte sequences into BPE subword tokens expands the left-context window per sequence, yielding the single largest BPB improvement (−0.3398 BPB).
  • RoPE Eliminates Position Caps: Rotary position embeddings require 0 learned parameters while generalizing better than fixed absolute position tables.
  • Weight Tying Unlocks Width: Tying the embedding to the LM head freed up 98,304 parameters, enabling 6 attention heads and 192 embedding dimension within the 2M budget.
